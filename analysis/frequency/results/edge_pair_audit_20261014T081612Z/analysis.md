# CEP-DVS 离线 Edge 与迁移配对审计

本报告核对 `edge_pair_audit_20261014T081612Z`。输入是同目录的 `run.json`、`pair_audit.csv`、`offline_edge_sample_channel.csv`，频谱参照来自此前的 [`smoke_20261014T072630Z`](../stage1_cepdvs/smoke_20261014T072630Z/analysis.md)。本次只读数据与源码，不训练或评估模型。

## 核对范围与结果

审计脚本 SHA-256 与当前本地 `audit_cepdvs_transfer.py` 一致。`run.json` 指向 `/home/user/Datasets/kpm-own/CEP-DVS` 下的离线 Edge、预处理 DVS 和真实 `pathFile.csv`；两侧均有 10,000 个被该 CSV 标注的 `.pt` 文件。脚本按 `get_edge2dvs_cepdvs` 当前实现的规则，以 Edge 文件数的前 90% 为训练索引、两侧比例均为 1，得到 9,000 个训练位置。`pair_audit.csv` 有 9,000 行，Edge/DVS ID 都依次为 `0～8999`，ID 和标签均 **9,000/9,000 相同**，没有非法 DVS 索引；Edge/DVS 文件 ID 集合相同。各类训练数为 `437～462`，这部分没有明显的类别缺席。

因此，上次提出的“排序或缺文件导致源/目标错位”**在本次审计使用的文件及标签表上没有发生**。`pretrain/edge2dvs_trainer.py` 用源标签计算目标分类损失，在这些已核对配对上不会因标签不一致而出错。但这还不是历史训练运行的凭证：本次没有读取历史日志、checkpoint 配置或实际训练时的数据根目录。

一个明确的路径限制：审计运行时远程 `dataloader/cepdvs.py` 的默认 `CEPDVS_ROOT` 仍是 `/home/user/kpm/kpm/Dataset/CEP-DVS`，而审计发现其中的 `pathFile.csv` **不存在**。审计脚本主动读取的是新数据根 `/home/user/Datasets/kpm-own/CEP-DVS/pathFile.csv`。因此，9,000/9,000 的结论是“若训练加载器使用这份 CSV，则索引配对正确”；不能宣称审计时未修改的默认加载器已经成功读取它。下一步应核实实际训练启动时的源码版本、路径覆盖或挂载方式，避免把文件层审计等同于训练过程审计。

后续核对了[数据路径说明](../../../../Docs/point1/数据集路径与格式说明.txt)，其中的 CEP-DVS 路径与审计实际输入一致。旧路径是**审计时默认源码与文档不一致**；本地已准备仅修正默认路径的补丁，远程尚需按[单批次核验说明](../../stage1_loader_path_check.md)同步并验证。历史 checkpoint 的运行路径仍待查。

## 相同 20 个 smoke 样本上的频谱

以下均为去空间均值后的频带功率占比，频带定义与前次 smoke 相同。离线 Edge 是迁移数据集 `.pt` 经加载器 `(edge-0.5)/0.5` 后的输入；该仿射变换的常数项被去均值消除，比例缩放不改变频带占比。

| 输入/通道 | 低频 % | 中频 % | 高频 % | 说明 |
|---|---:|---:|---:|---|
| 在线双 Sobel，两个相同通道 | 44.18 | 34.05 | 21.77 | RGB→Edge 预训练链 |
| 离线 Edge 通道 0 | 41.49 | 37.33 | 21.18 | 当前预处理脚本定义为水平梯度幅值 |
| 离线 Edge 通道 1 | 40.90 | 35.18 | 23.93 | 当前预处理脚本定义为垂直梯度幅值 |
| 处理后 DVS 负极性 | 19.85 | 29.92 | 50.23 | 真实事件链 |
| 处理后 DVS 正极性 | 18.21 | 28.27 | 53.53 | 真实事件链 |

离线 Edge 的两通道高频均值与在线 Sobel 接近，但结构不等价：在线两个通道的相关系数为 **1**，离线 Edge 两通道在 20 个样本上的平均相关系数约 **-0.0023**，范围 `-0.173～0.130`。离线 Edge 通道 0 相对在线 Sobel 的高频占比平均仅低 `0.58` 个百分点，但逐样本差值范围约 `-11.36～+6.79` 个百分点；通道 1 平均高 `2.16` 个百分点，逐样本差值约 `-12.60～+16.82` 个百分点。**均值相近不能替代实际输入或逐样本对齐。**本次读取了保存的 Edge `.pt`，尚未从 RGB 重建核对其生成版本；表中的方向含义依据当前 `preprocess_cepdvs_rgb2edge.py`，应作为待核实的代码来源。

处理后 DVS 的高频占比仍比对应离线 Edge 通道分别高约 **29.05、29.60 个百分点**，两组均为 20/20 个样本同向。这里的“对应”只是通道编号，离线 Edge 的方向通道与 DVS 的负/正极性没有语义对应；这个数值是描述性对照，不是传递增益或任务重要性。

离线 Edge 原文件的非零像素比例平均约 **99.2%**，加载后为 **100%**；处理后 DVS 负/正极性分别约 **11.0%/9.74%**。连续梯度和事件帧的非零阈值含义不同，不能把这些百分比直接当作物理事件密度。更值得后续测量的是值域：加载器把原 Edge 的 `0` 映射到 `-1`，此次 20 个样本两个通道的加载后最小值均接近 `-1`；DVS 输入则是稀疏、非负响应。默认 `time_encoder` 还将静态 Edge 重复到各时间步，而 DVS 保留动态帧。这些是输入机制差异，尚未量化它们在网络中的影响。

20 个参考 ID 在离线 Edge 中全部找到，20 个 `.pt` 内保存的标签与 CSV 标签一致。每类仍仅 1 个样本；离线频谱结论不能外推为类别差异，也没有 checkpoint 或准确率证据。

## 下一步决策

1. **先核实训练入口路径。** 在远程确认 `dataloader/cepdvs.py` 实际默认路径、历史训练命令、日志与 checkpoint；若新实验要读当前数据根，应显式修正/传入 CSV 根目录并重新做数据加载器级别的 1 个 batch 核验。不要把本次审计视为已验证未修改训练入口。
2. **再扩展输入统计。** 固定 ID，至少每类 5 个样本，补充离线 Edge 的有符号值分布、实际 `time_encoder` 输出和 DVS 首/末帧活动，分开报告方向、极性、稀疏度和时间结构。
3. **之后再做阶段 2。** 选已确认配置的 DVS baseline/checkpoint，在相同 DVS 样本上采集输入层与前两次池化前后的膜电位、脉冲率和空间频谱；目前不能从输入频谱推出网络丢失了哪个频带。
